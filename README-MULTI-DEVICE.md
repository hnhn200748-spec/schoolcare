# SchoolCare — ใช้งานจากหลายเครื่อง

ชุดนี้เชื่อมฐานข้อมูลกลาง Supabase ไว้แล้วใน `supabase-config.js` จึงสามารถให้หลายเครื่องใช้งานข้อมูลคำขอชุดเดียวกันได้ **เมื่อทุกเครื่องเปิดเว็บไซต์จาก URL เดียวกัน** และมีการตั้งค่า Supabase ถูกต้อง

## วิธีเปิดให้เครื่องอื่นใช้งาน (แนะนำ: GitHub Pages)

1. แตกไฟล์ ZIP นี้ในคอมพิวเตอร์
2. เข้าสู่ GitHub และสร้าง repository ใหม่ เช่น `schoolcare`
3. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ไปไว้ที่ root ของ repository (ตำแหน่งเดียวกับ `index.html`) แล้วกด Commit
4. เปิด repository → **Settings → Pages**
5. ในส่วน Build and deployment เลือก **Deploy from a branch**, เลือก branch `main` และ folder `/ (root)` แล้วกด Save
6. รอให้ GitHub Pages แสดง URL เว็บไซต์ เช่น `https://ชื่อผู้ใช้.github.io/schoolcare/`
7. เปิด URL นั้นจากมือถือหรือคอมพิวเตอร์เครื่องอื่น แล้วลองแจ้งซ่อม/ติดตามคำขอ

> อย่าเปิดไฟล์ `index.html` โดยตรงด้วยการดับเบิลคลิก (`file://`) เพราะบางเบราว์เซอร์อาจบล็อกการทำงานหรือการเชื่อมต่อ ควรเปิดผ่านเว็บไซต์ที่เผยแพร่แล้ว

## สถานะการเชื่อมต่อฐานข้อมูล

ไฟล์ `supabase-config.js` มี Project URL และ publishable/anon key อยู่แล้ว โค้ดฝั่งเว็บใช้ key สำหรับผู้ใช้ทั่วไป ไม่ควรใส่ `service_role` หรือ secret key ลงในเว็บหรือ GitHub

ก่อนใช้งานจริง ให้ตรวจสอบใน Supabase ว่าได้รัน `supabase-schema.sql` สำเร็จแล้ว หากเป็นฐานข้อมูลเดิมและมีตารางอยู่แล้ว ให้อ่านส่วน migration ใน README เดิม/ไฟล์ `supabase-migrate-existing-table.sql` ก่อน ไม่ควรรัน migration โดยไม่ตรวจสอบฐานข้อมูลเดิม

## ทดสอบข้ามอุปกรณ์

1. เปิดเว็บไซต์จากเครื่อง A แล้วส่งคำขอทดสอบ จด **หมายเลขคำขอ** และใช้เบอร์ติดต่อที่กรอกไว้
2. เปิด URL เดียวกันจากเครื่อง B ไปหน้า **ติดตามสถานะ**
3. กรอกหมายเลขคำขอและเบอร์ติดต่อเดียวกัน ควรเห็นคำขอเดียวกันจากฐานข้อมูลกลาง
4. ล็อกอินหน้าเจ้าหน้าที่เพื่อเปลี่ยนสถานะ แล้วตรวจสอบจากเครื่อง B อีกครั้ง

## ข้อจำกัดที่ควรรู้

- คำขอและสถานะอยู่ใน Supabase กลาง จึงเรียกดูได้จากอุปกรณ์อื่นผ่านหน้า **ติดตามสถานะ** ด้วยหมายเลขคำขอและเบอร์ติดต่อ
- หน้า **ประวัติการแจ้งซ่อม** เก็บรายการอ้างอิงไว้ใน `localStorage` ของเบราว์เซอร์ที่ส่งคำขอ ดังนั้นรายการประวัติเดิมจะไม่ปรากฏอัตโนมัติบนเครื่องใหม่ แต่ยังติดตามได้ด้วยหมายเลขคำขอและเบอร์ติดต่อ
- หน้าเจ้าหน้าที่ต้องมีบัญชี Supabase Auth และ `profiles.role='staff'` ตามคำแนะนำใน `README-SETUP.md`
- หากหน้าเว็บโหลดได้แต่ส่ง/ค้นหาไม่ได้ ให้ตรวจสอบการตั้งค่า Supabase, schema/RPC, และนโยบาย RLS ใน Supabase Dashboard
- ห้ามเผยแพร่ `service_role` key, รหัสผ่าน หรือข้อมูลลับใน repository

## เอกสารตั้งค่าเดิม

ดู `README-SETUP.md` สำหรับขั้นตอนตั้งค่า Supabase และสร้างบัญชีเจ้าหน้าที่ รวมถึงไฟล์ SQL สำหรับ schema/migration และแก้ปัญหา RPC
